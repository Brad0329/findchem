# MSDS 성분 정리표

MSDS PDF → 제품별 구성성분 표(제품 · 구분 · 성분 · CAS · 함유량 · 물질 분류 · 비고 · 원본 파일).
**PDF 읽기는 네가 하고, 분류 문구·비고·색칠·엑셀은 `scripts/build_table.py`가 한다.** 분류나 비고를 손으로 쓰지 않는다.

## 순서

1. **입력 확인** — 채팅에 첨부된 PDF가 있으면 그것을 쓴다. 사용자가 Drive 폴더를 말했으면 Drive 커넥터로 그 폴더의 PDF를 찾아 읽는다.
   둘 다 없으면 어느 쪽인지 묻는다. Drive 커넥터가 없으면 그 사실을 알리고 첨부를 부탁한다.
   읽을 파일 목록(개수 포함)을 먼저 한 줄로 알린다. 일부만 읽게 되면 몇 건 중 몇 건인지 말한다 — 조용히 빼지 않는다.
2. **추출** — 파일마다 아래 '읽는 법'대로 제품명과 3번 성분을 뽑아 `extract.json`에 쓴다(형식은 아래).
3. **CAS 목록** — `python scripts/build_table.py cas extract.json` 출력(JSON 배열)을 **그대로** `classify_cas`의 `cas`로 넣어 한 번 부른다.
   200개를 넘으면 나눠 부르고 응답의 `items`를 순서대로 이어 붙인다. CAS가 하나도 없으면 이 단계를 건너뛰고 `{"items": []}`를 쓴다.
4. **응답 저장** — `classify_cas` 응답 JSON을 **고치지 말고 통째로** `classify.json`에 쓴다.
5. **표** — `python scripts/build_table.py table extract.json classify.json` → 나온 요약 줄과 마크다운 표를 **화면에 그대로** 보인다.
   오류(종료 코드 1)가 나면 메시지대로 extract.json이나 classify.json을 고쳐 다시 돌린다. 표를 손으로 만들어 대신하지 않는다.
6. **확인 요청과 저장 방식 질문** — 표 아래에 짧게 덧붙인다:
   - 읽기 어려웠던 파일·행(note를 단 것)을 짚어 "원문과 대조해 달라"고 한다
   - 저장 방식을 묻는다: **① 엑셀 파일로 받기 ② Google Drive에 저장 ③ 화면만 보고 끝내기**
   사용자가 표를 고치라고 하면 extract.json을 고치고 5부터 다시 한다.
7. **저장**
   - ① `table ... --xlsx <파일명>.xlsx`로 만들어 채팅에서 내려받을 수 있게 준다. 파일명 기본값 `MSDS_성분정리_YYYYMMDD.xlsx`
   - ② 먼저 ①처럼 엑셀을 만들고, 어느 Drive 폴더에 둘지 묻는다(입력이 Drive 폴더였으면 그 폴더를 기본으로 제안). Drive 커넥터로 올린 뒤 파일 링크를 알린다.
     커넥터가 없거나 올리기에 실패하면 그 사실과 이유를 말하고 ①로 준다
   - ③ 아무것도 만들지 않는다

## 읽는 법 (실물 10건 전수조사에서 나온 함정)

3번 제목 "구성성분의 명칭 및 함유량"만 공통이고 **모양은 파일마다 다르다.** 텍스트로 추출된 순서를 믿지 말고 행을 다시 맞춘다.
- 가로 표 / 세로 라벨-값(화학물질명: … CAS 번호: … 함유량: …) / "가. 나. 다. 라." 목록 / **열 단위로 추출**(이름만 쭉, CAS만 쭉, 함유량만 쭉 나온다 — 순서로 짝짓는다)
- 표가 3번 제목 밖(2번 한가운데)으로 튀어 있을 수 있다 — 3번이 비어 보이면 앞뒤 절을 본다
- 함유량이 쪽 바닥글(회사명·쪽 번호) 뒤로 밀려 있을 수 있다
- 긴 물질명·이명(관용명)이 줄바꿈으로 쪼개져 다음 행과 섞인다 — 한 성분은 CAS 하나에 대응한다는 것으로 경계를 잡는다
- 관용명·이명이 여럿이면 **성분 이름은 3번 표의 첫 이름** 하나만 쓴다

옮기는 규칙:
- **제품명** = 1번 항목의 제품명 원문. 파일명은 제품명이 아니다
- **함유량은 원문 그대로**(`50.0 >`, `58-68%`, `60~70`, `>99-<=100`, `1-0%`, `≥99%`, `99.5% 이상`). 숫자로 바꾸거나 단위를 붙이지 않는다
- **CAS는 원문 그대로**(`000065-85-0`처럼 앞 0이 있어도 그대로 — 스크립트가 비고에 원문을 남긴다). 단 `CAS No.` 같은 접두어와 공백은 뺀다
- CAS 칸이 비었거나 `-`, `자료없음`, `영업비밀`이면 `cas`는 빈 문자열. 원래 칸에 적힌 표기는 `note`에 (`CAS 칸 표기 '- / -'`)
- KE 번호·EC 번호(`203-466-5`처럼 가운데가 3자리)는 CAS가 아니다 — 넣지 않는다
- **없는 것은 빈칸이다. 지어내지 않는다.** 물질명으로 CAS를 추측해 채우지 않는다
- 확신이 없는 행(쪼개진 이름을 이어 붙임, 열 단위 짝짓기, 바닥글 뒤 값)은 `note`에 무엇이 불확실한지 적는다 — 화면에서 사용자가 대조한다
- 15번(법적 규제 현황)은 분류 출처로 쓰지 않는다. 분류는 오직 classify_cas

## extract.json 형식

```json
{"products": [
  {"product": "1번 제품명", "file": "원본 파일명.pdf",
   "components": [
     {"name": "성분명", "cas": "123-86-4", "content": "50.0 >"},
     {"name": "영업비밀", "cas": "", "content": "60~70", "note": "CAS 칸 표기 '- / -'"}
   ]}
]}
```
성분 순서는 MSDS 3번 표의 순서를 따른다. 성분이 하나도 안 읽히는 파일은 빼지 말고 사용자에게 그 파일을 말한다.

## 표에 대해 사용자에게 설명할 때

- 물질 분류는 「유해화학물질의 규정수량에 관한 규정」 별표 2·3 기준이다. "비해당"은 이 고시의 분류가 없다는 뜻이지 다른 법령의 규제가 없다는 뜻이 아니다
- **함유량이 함량기준에 미달하는지는 판정하지 않았다** — 비고의 함량기준과 함유량을 사람이 비교한다
- 규정수량 값이 필요하면 그 물질만 `search_chemical`로 따로 본다
