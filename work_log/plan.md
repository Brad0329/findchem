# FindChem 전체 계획 (단일 원본)

> PLAN MODE에서 최초 작성/주요 변경 시 갱신. Phase 완료 시 메인 agent가 체크박스 `[x]` + 완료일.
> `Phase_XXX.md`는 실패한 접근·버린 대안이 있을 때만 만든다.

## 시스템 개요
- FindChem은 물질명(국문·영문, 부분 일치, 띄어쓰기 무시)이나 CAS 번호를 넣으면 환경부 고시 「유해화학물질의
  규정수량에 관한 규정」에서 규정수량을 찾아 준다. 대상은 [별표 2] "인체·생태 유해성" 1,557건과 [별표 3]
  "사고대비물질" 100건이다. 사용자는 본인과 사내 소수다. 고시가 개정되면 각 기기에서 두 PDF를 올려 원천자료를
  바꾼다. 요구사항 상세는 docs/REQUIREMENTS.md에 있다.

## 아키텍처
- **Flutter 한 벌**로 Android APK와 웹을 만든다. 서버와 DB는 없다.
- **데이터**: 두 별표를 항목 단위로 담은 JSON 1개(약 561KB)를 앱에 번들한다. 앱이 시작할 때 메모리에 올려 검색한다
  (docs/SCHEMA.md).
- **파서**: **Dart PDF 파서 하나**를 두 곳에서 쓴다. ① 개발 PC에서 번들 JSON을 만들 때 ② 앱 안의 원천자료
  update(F-002). Python 파서는 두지 않는다. 같은 규칙이 두 곳에 생기기 때문이다.
- **원천자료 update 저장본**: 기기 저장소에 따로 둔다(Android는 앱 저장소, 웹은 브라우저 저장소). 저장본이 있으면
  그것을 쓰고, 없으면 번들본을 쓴다. 되돌리기는 저장본을 지우는 것이다.
- **외부 연동**: 없음. 화학물질 API는 프로젝트가 끝난 뒤 검토한다(보류 항목).

- **외부 원천 조사(중단, 2026-09-11)** — 대상: law.go.kr 고시 연혁·DRF API, NCIS, 공공데이터포털
  API·파일데이터, KOSHA MSDS API. 결과를 받기 전에 중단했다. 그 뒤 API만 따로 확인했다(아래). 알려진 것:
  ① PDF 본문에 고시 번호·시행일이 없다. 메타데이터 생성일은 2026-07-20이고, 고유번호 최대값은 `2026-1-1353`이다.
  ② law.go.kr은 WebFetch로 본문을 가져오지 못했다. 재개 시점(2026-09-11 사용자 결정): **이 프로젝트가 끝난 뒤
  API 추가를 다시 검토한다.** 첫 단계는 law.go.kr 행정규칙 연혁을 브라우저로 열어 이 PDF가 최신판인지 확인하는 것이다.
  - **API 문서 확인(2026-09-11)**: 공공데이터포털의 Swagger 명세와 목록 페이지를 봤다. 15149420만 실제로 호출했다(아래 '실호출 결과').
    - [한국환경공단_화학물질 정보 조회 서비스](https://www.data.go.kr/data/15149420/openapi.do)
      - 관리부서는 화학물질관리처 화학물질정보부다. 이 부서가 화학물질정보처리시스템을 운영하는 곳으로 보인다(추정).
      - CAS·물질명·고유번호로 검색한다. 응답은 `casNo`, `korexst`, `sbstnNmKor/Eng`, 분자식·분자량,
        `typeList[]{sbstnClsfTypeNm 물질분류유형명, unqNo 고유번호, contInfo 함량정보, excpInfo 예외정보, ancmntYmd 고시일자,
        ancmntInfo 고시정보}`이다.
      - **규정수량 필드는 없다.** 인증키가 필요하고, 개발 계정 한도는 10,000건이다. 최종 수정일은 2025-09-16이다.
    - [한국환경공단_유독물GHS 정보 조회 서비스](https://www.data.go.kr/data/15149423/openapi.do): 신호어, 그림문자, UN번호,
      M계수, 유해성분류를 준다. 규정수량은 없다.
    - [화학물질안전원_화학물질안전관리정보](https://www.data.go.kr/data/15072442/openapi.do): 응급 증상(흡입, 피부 등)을 준다.
      규정수량은 없다.
    - **실호출 결과(2026-09-11, 표본 3건)**: 15149420 `chemSbstnList`를 불렀다. 키는 `.env`의 `DATA_GO_KR_KEY`에 있다.
      - `searchGubun=3`(고유번호), `searchNm=97-1-4` → **0건**. 고유번호 검색이 이 형식을 받지 않는 것으로 보인다. 원인은 모른다.
      - `searchGubun=2`(CAS), `13516-27-3` → 구아자틴이 나온다. `typeList`에 `{sbstnClsfTypeNm:"인체등유해성물질",
        unqNo:"97-1-4", contInfo:"인체급성유해성 : 1%, 생태유해성 : 25%", ancmntInfo:"화학물질안전원고시 제2025-19호"(20250807)}`가 있다.
        **PDF의 고유번호·함량기준(급성 1, 생태 25)과 일치한다.**
      - `searchGubun=2`(CAS), `7758-95-4`(염화납 — PDF에 개별 항목이 없다) → `typeList`에 `{sbstnClsfTypeNm:"인체등유해성물질 세분류",
        unqNo:"97-1-9", contInfo:"인체만성유해성 : 0.3%, 생태유해성 : 25%"}`가 있다. **묶음 항목("납과 그 화합물")에 속하는지를
        API가 알려 준다 — 가설 확인(표본 1건).** 같은 응답에 제한물질(`06-5-8`), 중점관리물질, 암·돌연변이성물질 분류도 온다.
      - 남은 문제: PDF에서 `97-1-9`는 21행이 함께 쓴다(납과 그 화합물, 무기 납화합물 등). 어느 행의 규정수량을 적용할지는
        고유번호만으로는 정해지지 않는다. `contInfo`의 구분·함량으로 행을 고르는 규칙이 필요하다. 규정수량 값 자체는
        API에 없어서 PDF가 여전히 원천이다.
