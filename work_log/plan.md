## 결정된 것 / 미정인 것

**확정**
- (2026-09-11, 사용자 결정) **데이터 원천 = `assets/`의 고시 별표 PDF 2개를 파싱해서 쓴다.**
  외부 API로 대체하는 안은 조사 도중 중단했다 — 사유: 조사 시간. 재개 조건은 '보류 항목'에 있다.
- (2026-09-11) **서버 DB는 두지 않는다.** 근거: 읽기 전용이고 사용자 데이터가 없다. 1,657건, JSON 약 561KB
  (gzip 88KB, 전수 실측). 정규화 데이터를 앱·웹에 정적으로 넣는다. 파싱 시 함정은 `Phase_001.md`에 있다.

- (2026-09-11, 사용자 결정) **스택 = Flutter 한 벌로 Android와 웹을 함께 만든다.** 버린 대안은 둘이다.
  웹 PWA 하나는 스토어 앱이 아니고, 네이티브와 웹을 따로 만들면 검색 규칙이 두 곳에 구현된다.
- (2026-09-11, 사용자 결정) **사용자 = 본인과 사내 소수.** APK를 직접 설치하고, 스토어에는 등록하지 않는다.
- ~~(2026-09-11) 고시가 개정되면 새 PDF를 다시 파싱하고 앱·웹을 재배포한다~~ → **같은 날 사용자 결정으로 대체:
  앱 설정의 '원천자료 update'(F-002)에서 PDF를 올리면 앱이 파싱해서 교체한다.** 원격 JSON 갱신은 여전히 하지 않는다.
  - 결과 1: **PDF 파서는 Dart로 하나만 둔다.** 앱에 넣는 JSON도 같은 Dart 파서로 만든다. Python 파서를 따로 두면
    같은 규칙이 두 곳에 생긴다.
  - 결과 2: **가장 위험한 항목은 "Dart(Android·웹)에서 이 PDF의 표를 pdfplumber만큼 추출할 수 있는가"이고, 아직
    모른다.** MVP에서 이것부터 실측한다. 실측 기준은 `Phase_001.md`의 불변식이다.
  - 결과 3: 올린 PDF로 만든 원천자료는 기기에 저장한다. 앱에 번들한 데이터와는 따로 둔다(SCHEMA.md).
- (2026-09-11, 사용자 결정) 앱 이름은 **FindChem**이다. 화면 용어는 별표2 → "인체·생태 유해성", 별표3 → "사고대비물질"이다.
- (2026-09-11, 사용자 결정) 검색 결과 화면은 목업대로 확정했다. 이름은 부분 일치로 찾는다. 두 표에 모두 있으면
  사고대비물질을 위에 두고 '우선 적용'을 표시하며, 인체·생태 유해성 값은 참고로 함께 보여준다.

- (2026-09-11, 사용자 결정) **CAS 검색 결과가 0건이면 안내를 띄운다: "염류·화합물 묶음 항목에 해당할 수 있으니
  이름으로도 검색해 보세요".** 이유: 원천 PDF에 CAS 없는 항목이 77건 있고, 어떤 CAS가 어느 묶음에 속하는지는
  PDF에 없다. REQUIREMENTS 초안을 쓸 때 F-001 수용 기준으로 옮긴다.
