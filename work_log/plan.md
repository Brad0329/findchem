> PLAN MODE에서 최초 작성/주요 변경 시 갱신. Phase 완료 시 메인 agent가 체크박스 `[x]` + 완료일.
> `Phase_XXX.md`는 실패한 접근·버린 대안이 있을 때만 만든다.

## 시스템 개요
- FindChem은 물질명(국문·영문, 부분 일치, 띄어쓰기 무시)이나 CAS 번호를 넣으면 화학물질안전원고시 「유해화학물질의
  규정수량에 관한 규정」에서 규정수량을 찾아 준다. 대상은 [별표 2] "인체·생태 유해성" 1,557건과 [별표 3]
  "사고대비물질" 100건이다. 사용자는 본인과 사내 소수다. 고시가 개정되면 각 기기에서 두 PDF를 올려 원천자료를
  바꾼다. 요구사항 상세는 docs/REQUIREMENTS.md에 있다.

## 아키텍처
- **Flutter 한 벌**로 Android APK와 웹을 만든다. 서버와 DB는 없다.
- **데이터**: 두 별표를 항목 단위로 담은 JSON 1개(약 561KB)를 앱에 번들한다. 앱이 시작할 때 메모리에 올려 검색한다
  (docs/SCHEMA.md).
- **파서**: **Dart PDF 파서 하나**를 두 곳에서 쓴다. ① 개발 PC에서 번들 JSON을 만들 때 ② 앱 안의 원천자료
  update(F-002). Python 파서는 두지 않는다. 같은 규칙이 두 곳에 생기기 때문이다.
- **원천자료 update 저장본**: 기기 저장소에 따로 둔다(Android는 앱 저장소, 웹은 브라우저 저장소). 저장본이 있으면
  그것을 쓰고, 없으면 번들본을 쓴다. 되돌리기는 저장본을 지우는 것이다.
- **외부 연동**: F-007(2026-09-14) — 앱·웹이 공공데이터포털 API 3종을 CAS로 **직접** 부른다. 키는 사용자가 설정에서 넣어
  기기에 저장한다(앱·웹에 키 없음). 서버는 없다. 규정수량은 API에 없어 계속 PDF가 원천이다.
- **LLM 판정(F-008, 2026-09-16)**: 앱·웹이 Anthropic API를 **직접** 불러, LLM이 우리 검색 함수(`lib/search/`)와 규칙 원문을
  **tool use 도구로** 쓰며 조합 질문(합산·초과 판정)에 답한다. 도구 응답 조립(조건 문장·커버리지·규칙 원문)은 **Dart 층 하나**
  (`lib/assist/`)이고, 개발 하네스인 `scripts/search_cli.dart` → `scripts/mcp_server.py`(PC 데스크톱 Claude용 MCP)도 같은 함수를
  통과시킨다. 근거는 모델 문장이 아니라 **앱이 도구 결과에서 직접** 그린다. 온라인 전용. 서버는 여전히 없다.
