# Phase 006 — 배포

## 실패한 접근과 원인

### 릴리스 서명 키: "비밀번호가 틀렸다"를 세 번 잘못 진단했다 (2026-09-12)

증상은 Gradle의 한 줄이었다: `Keystore was tampered with, or password was incorrect`.
이 메시지는 **저장소 비밀번호·키 비밀번호·파일 손상을 구분하지 않는다.** 그래서 원인을 세 번 잘못 짚었다.

1. **파일 형식을 의심했다** → `key.properties`의 BOM·백슬래시 이스케이프·값 끝 공백·줄바꿈을 전수 확인
   (일회성 스크립트, 비밀번호 값은 출력하지 않게 짰다). **전부 정상** — 형식 문제가 아니었다.
2. **키 비밀번호만 다르다고 판단했다** → 근거는 `keytool -list -v -alias`가 통과한 것이었다
   ("저장소 비밀번호는 맞으니 남은 건 키 비밀번호"). **이 추론이 틀렸다** — 아래 참조.
3. **PKCS12로 다시 만들게 했다**(키·저장소 비밀번호가 갈릴 수 없는 형식) → 그제서야 진짜 원인이 나왔다:
   `keytool 오류: ... getSecretKey failed: **Password is not ASCII**`.

**진짜 원인: 한/영이 한글 상태에서 비밀번호를 쳤다.** 비밀번호 입력은 화면에 찍히지 않아 IME 상태를
눈으로 확인할 수 없다. `dmsw0114`가 `으뭐0114`로 들어갔고, **JKS는 그것을 그대로 받아 저장했다.**
파일에 적은 ASCII 값과는 영영 안 맞는다.

②의 추론이 왜 틀렸나: `keytool -list`를 칠 때도 IME가 같은 상태라 **같은 한글 문자열이 다시 들어가
통과했다.** "통과했으니 이 비밀번호가 맞다"가 성립하려면 두 번의 입력이 독립이어야 하는데,
같은 사람이 같은 IME 상태로 치면 독립이 아니다. **에코되지 않는 입력은 두 번 쳐도 한 번의 증거다.**

교훈은 구조로 옮겼다 — `팩_Flutter_Android.md` '릴리스 서명 키'에 ASCII 함정과 PKCS12 지정을 적었고,
PKCS12는 생성 시점에 거부하므로 다음 사람은 두 시간이 아니라 첫 명령에서 알게 된다.

### 곁가지로 걸린 것

- keystore를 지우려니 "다른 프로세스가 사용 중" — 실패한 릴리스 빌드의 **Gradle 데몬**이 파일을 잡고 있었다.
  `android/gradlew --stop`으로 풀린다.
- PowerShell에서 경로에 공백이 있는 실행 파일은 **호출 연산자 `&`** 없이는 `예기치 않은 '-genkeypair' 토큰`으로
  죽는다. 처음에 bash 형식(`"/c/Program Files/..."`)을 그대로 드려서 한 번 헛돌았다.
