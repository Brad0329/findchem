# FindChem 에이전트 트랙 계획 (`agent` 브랜치)

> 이 파일이 에이전트 트랙의 **단일 원본**이다. master 트랙(앱·웹, F-006~F-009, Phase 007)은 `work_log/plan.md`.
> 요구사항·수용 기준은 `docs/REQUIREMENTS_AGENT.md`(번호 `A-NNN`, F 번호와 섞지 않는다).

## 목적과 범위

- FindChem을 **에이전트가 쓰는 꾸러미**로 만든다: ① 원격 MCP 서버(데이터·조회 도구·계산·검증 도구 — 틀리면 안 되는 것)
  ② 스킬/Cowork 플러그인(서류별 작성 지침·서식·예시 — 일하는 방식) ③ 수용 테스트(과거 제출본으로 채점).
  에이전트는 Cowork, 저장소는 Google Drive. 앱·웹은 사람용 조회 화면으로 남고 데이터·Dart 코드를 서버와 같이 쓴다.
- 배경·근거: 검토 문서 [FindChem 에이전트 우선 전환 검토](https://claude.ai/artifact/Txdi8q8TpMKzKEYP6hTUKT)와
  plan.md '미정'의 '에이전트 우선 전환' 항목. **아직 뒤집지 않은 master 결정**: "서버 DB 없음", "MCP는 실험 하네스".
  이 트랙을 master에 합치는 것은 방향이 확정될 때 한 번이고, 그때 CLAUDE.md 첫 줄·그 두 결정을 함께 고친다.

## 브랜치 운영 (사용자 결정 2026-10-02)

- 에이전트 트랙의 개발·테스트는 전부 `agent` 브랜치에서 한다. 웹 배포는 master push로만 돌므로 이 브랜치는 배포에 닿지 않는다.
- master의 변경은 주기적으로 `agent`에 병합한다(master → agent 한 방향). `agent` → master는 방향 확정 시 한 번.
- 세션 훅 `session_context.py`는 이 파일이 있으면 plan.md 대신 이것을 주입한다(이 브랜치에만 있는 파일이라 master에는 영향 없음).
- 브랜치 이름이 `mcp`가 아니라 `agent`인 이유: 만드는 것이 MCP 서버만이 아니라 스킬·수용 테스트까지라서.

## Phase 체크리스트

> 순서는 "가장 위험한 것 먼저". 번호는 발급 순서일 뿐 — 착수 순서는 이 목록 순서를 따른다.
> 각 항목은 착수할 때 `REQUIREMENTS_AGENT.md`에 수용 기준을 먼저 쓴다.

- [ ] **A-001 원격 MCP 시범** — 기존 도구 2개(`search_chemical`·`get_rule`)를 공개 HTTPS로 올려 Cowork(폰·PC)에서 붙인다.
  서버가 만든 파일(PDF)을 Cowork가 받는 길도 여기서 잰다(plan.md '미정'의 1단계 첫 실측). **기본 구조 변경 — 착수 전 사용자 결정**:
  호스팅(서버리스/상시)·언어(Dart면 `lib/search`·`lib/assist`를 그대로 쓴다)·인증(처음엔 인증 없는 읽기 전용, 필요 시 OAuth)
- [ ] **A-002 데이터 출처 조사** — 위험노출수준(ERPG-2·PAC-2), 시나리오 규정수량 기준표(400·100·5kg), 별지1의 규정수량 표기("*400 / -")가
  고시 별표 2·3과 같은 출처인지. `researcher`로
- [ ] **A-003 물성 조회 도구** — KOSHA MSDS(정식 주소, plan.md 보류 항목 'KOSHA MSDS 조회 서비스 실측')에서 비중·증기압·폭발한계·TWA·GHS·H코드.
  값은 원문 그대로 + 단위를 분리해 돌려준다(자유 문자열 — 파싱 실패는 실패라고 돌려준다)
- [ ] **A-004 계산 도구** — 작성수준 판정(설비 용량 × 비중 → 물질별 최대보유량 → 하위·상위 규정수량 비교),
  함량미만 판정·장외평가 시나리오 대상 산정(함량 vs 함량기준, 저확산물질). 에이전트 암산 금지 — 코드로
- [ ] **A-005 검증 도구 `verify_draft`** — 초안의 물질 값·단위를 공식 데이터와 대조. 시험 사례 = 사례 A 제출본의 불일치(아래 조사 기록)
- [ ] **A-006 스킬** — `규정수량-판정`(F-008 시스템 프롬프트 이관) + `계획서-작성`(별지 서식·칸별 규칙·비식별 예시)
- [ ] **A-007 수용 테스트(사례 A)** — 아래 '수용 테스트 설계'대로 실행·채점. MCP·스킬을 최선으로 만든 **뒤에** 돈다

## 수용 테스트 설계 (사용자 2026-10-02)

- **방식**: 과거 제출본 1건을 "사업장이 준 것"과 "사람이 직접 쓴 것"으로 나눠 복사한다. 에이전트에게는 입력 폴더 + 목차만 주고
  목차대로 작성하게 한 뒤, 결과를 직접 쓴 판(정답)과 대조한다.
  **FindChem 없이 하는 기준선 테스트는 하지 않는다**(사용자 결정 2026-10-02 — MCP를 최선으로 만든 뒤에 돌리는 테스트다).
- **분리 규칙**: `입력/` = 사업장 증빙 + 프로그램 출력(KORA 출력은 사람이 쓴 것이 아니라 입력). `정답/` = 에이전트에 연결하지 않는다
  (하나라도 보이면 베낀다). 원본은 건드리지 않고 Drive에서 복사만.
- **채점(돌리기 전에 고정)**: 세 표의 칸 단위 일치율(별지1 작성수준, 1.2 물질 목록·명세, 장외평가 시나리오 대상 산정표) +
  지어낸 값 수 + 입력에 없는 값을 "자료 없음"으로 표시했는지 + 검토 시간. 서술 장(4~6)은 한 절만 표본으로.
- **원본 파일(hwp·xlsx)은 필수가 아니다**: 정답 대조는 텍스트가 살아 있는 PDF로 되고, 빈 별지 서식은 국가법령정보센터에서 받는다.
  엑셀 계산 파일이 있으면 수식(비중 환산·합산)을 계산 도구 참고로 받는다(선택). 제출 형식이 hwp여야 하는지는 친구에게 한 번 묻는다.

## 조사 기록

- **사례 A — 화학사고예방관리계획서 합본 제출본(2025)** 전수 조사(2026-10-02, 서브에이전트, 읽기 전용).
  위치: Drive(dannybrad0602 계정) `FindChem/assets/이앤켐/` 아래 2025 계획서 합본 폴더. **실제 사업장 서류라 저장소에 올리지 않는다**(.gitignore).
  폴더 19개·파일 170개 전부 훑음(PDF 169 + zip 1, hwp·xlsx 원본 없음). 내용을 읽은 것은 본문 위주 16개, 도면류 85개·첨부 대부분은 안 읽음
  - **목차**: 0 작성수준·요약서 / 1.1 일반정보 / 1.2 물질 목록·유해성 + MSDS / 1.3 입지 / 2.1 공정안전(PFD 33·P&ID 52) /
    2.2 안전장치(확산방지·감지기·안전밸브·대기) / 3 장외평가 / 4 사전관리방침 / 5 내부비상대응 / 6 외부비상대응.
    서식은 「화학사고예방관리계획서 작성 등에 관한 규정」 별지(제1·7·8~14·15·31호 등). 파일명 번호는 폴더(목차) 번호와 다른 체계가 섞여 있다
  - **FindChem과 직접 맞닿는 것**: 별지1 작성수준 판정(용량×비중 합산 vs 하위·상위 규정수량), 1.2 물질 목록
    (열: 연번·물질명·CAS·고유번호[사고대비 번호 / 유독물질 번호]·상태·농도·비중·폭발한계·독성구분[GHS]·위험노출수준[ERPG-2/PAC-2]·TWA·증기압·부식성),
    별지7 물질별 유해성, 장외평가 시나리오 대상 산정표(설비별 함량·비중·취급량 vs 시나리오 규정수량 → 표준/소량/함량미만/미대상, 저확산물질 제외)
  - **장외평가는 KORA(5.15.8) 출력**이다 — 에이전트가 대신할 수 없다(입력으로 받는다). 끝점은 ERPG-2/PAC-2, 물성은 KORA 내장 DB
  - **4~6장 서술은 판단보다 사업장 고유 정보**(조직·연락처·대피경로)가 대부분 — 스킬보다 사업장 입력의 몫이 크다
  - **제출본 안의 불일치**(손 전기의 흔적 — `verify_draft`의 시험 사례): 같은 물질 비중이 표마다 g/L과 무차원으로 다른 값,
    목록 비중과 KORA 액상밀도 차이, 같은 설비 용량이 장치명세·산정표·KORA에서 셋 다 다름, 증기압 열 제목 단위(mmHg)와 값 단위(hPa·kPa·Pa) 불일치,
    위험노출수준 칸에 ERPG-2와 PAC-2 혼재
  - **개인정보 다량**(인근 사업장 연락처, 담당자 실명·휴대전화) — 에이전트로 다룰 때와 스킬 예시를 만들 때 비식별화가 필요하다
