# FindChem 에이전트 트랙 계획 (`agent` 브랜치)

> 이 파일이 에이전트 트랙의 **단일 원본**이다. master 트랙(앱·웹, F-006~F-009, Phase 007)은 `work_log/plan.md`.
> 요구사항·수용 기준은 `docs/REQUIREMENTS_AGENT.md`(번호 `A-NNN`, F 번호와 섞지 않는다).

## 목적과 범위

- FindChem을 **에이전트가 쓰는 꾸러미**로 만든다: ① 원격 MCP 서버(데이터·조회 도구·계산·검증 도구 — 틀리면 안 되는 것)
  ② 스킬/Cowork 플러그인(서류별 작성 지침·서식·예시 — 일하는 방식) ③ 수용 테스트(과거 제출본으로 채점).
  에이전트는 Cowork, 저장소는 Google Drive. 앱·웹은 사람용 조회 화면으로 남고 데이터·Dart 코드를 서버와 같이 쓴다.
- 배경·근거: 검토 문서 [FindChem 에이전트 우선 전환 검토](https://claude.ai/artifact/Txdi8q8TpMKzKEYP6hTUKT)와
  plan.md '미정'의 '에이전트 우선 전환' 항목. **아직 뒤집지 않은 master 결정**: "서버 DB 없음", "MCP는 실험 하네스".
  이 트랙을 master에 합치는 것은 방향이 확정될 때 한 번이고, 그때 CLAUDE.md 첫 줄·그 두 결정을 함께 고친다.

## 브랜치 운영 (사용자 결정 2026-10-02)

- 에이전트 트랙의 개발·테스트는 전부 `agent` 브랜치에서 한다. 웹 배포는 master push로만 돌므로 이 브랜치는 배포에 닿지 않는다.
- master의 변경은 주기적으로 `agent`에 병합한다(master → agent 한 방향). `agent` → master는 방향 확정 시 한 번.
- 세션 훅 `session_context.py`는 이 파일이 있으면 plan.md 대신 이것을 주입한다(이 브랜치에만 있는 파일이라 master에는 영향 없음).
- 브랜치 이름이 `mcp`가 아니라 `agent`인 이유: 만드는 것이 MCP 서버만이 아니라 스킬·수용 테스트까지라서.

## 수용 테스트 설계 (사용자 2026-10-02)

- **방식**: 과거 제출본 1건을 "사업장이 준 것"과 "사람이 직접 쓴 것"으로 나눠 복사한다. 에이전트에게는 입력 폴더 + 목차만 주고
  목차대로 작성하게 한 뒤, 결과를 직접 쓴 판(정답)과 대조한다.
  **FindChem 없이 하는 기준선 테스트는 하지 않는다**(사용자 결정 2026-10-02 — MCP를 최선으로 만든 뒤에 돌리는 테스트다).
- **분리 규칙**: `입력/` = 사업장 증빙 + 프로그램 출력(KORA 출력은 사람이 쓴 것이 아니라 입력). `정답/` = 에이전트에 연결하지 않는다
  (하나라도 보이면 베낀다). 원본은 건드리지 않고 Drive에서 복사만.
- **채점(돌리기 전에 고정)**: 세 표의 칸 단위 일치율(별지1 작성수준, 1.2 물질 목록·명세, 장외평가 시나리오 대상 산정표) +
  지어낸 값 수 + 입력에 없는 값을 "자료 없음"으로 표시했는지 + 검토 시간. 서술 장(4~6)은 한 절만 표본으로.
- **원본 파일(hwp·xlsx)은 필수가 아니다**: 정답 대조는 텍스트가 살아 있는 PDF로 되고, 빈 별지 서식은 국가법령정보센터에서 받는다.
  엑셀 계산 파일이 있으면 수식(비중 환산·합산)을 계산 도구 참고로 받는다(선택). 제출 형식이 hwp여야 하는지는 친구에게 한 번 묻는다.
