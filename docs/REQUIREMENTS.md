# FindChem 요구사항 (단일 원본)

> 기능 요구사항 + 수용 기준의 단일 원본. **요구사항이 바뀌면 대화로 합의만 하지 말고 이 파일을 즉시 갱신.**
> 완료 판정은 항상 이 문서를 기준으로 한다(에이전트를 쓰든 직접 대조하든).
> **새 F-번호는 CLAUDE.md의 '요구사항 ID 대장'에서 받아간다. 번호 재사용 금지.**

## 시스템 목표
- 물질명이나 CAS 번호를 넣으면 환경부 고시 「유해화학물질의 규정수량에 관한 규정」에서 그 물질의 규정수량을
  바로 찾아 준다. 대상은 두 표다.
  - [별표 2] 인체급성·인체만성·생태유해성 물질별 규정수량
  - [별표 3] 사고대비물질별 규정수량
- 사용자는 본인과 사내 소수다. Android 앱과 웹으로 제공하며, 둘 다 Flutter 한 벌로 만든다. 서버는 없다.

## 용어 (화면 표시) — 2026-09-11 사용자 결정
- [별표 2] → **"인체·생태 유해성"**, [별표 3] → **"사고대비물질"**.
- 화면에는 이 두 이름을 쓰고 "별표2", "별표3"은 쓰지 않는다. 데이터 내부 식별자는 SCHEMA.md를 따른다.

## 사용자/권한
- 역할을 구분하지 않는다. 앱을 가진 사람은 누구나 조회할 수 있고 원천자료 update(F-002)도 할 수 있다.
  (AI가 채운 기본값이다. 달라지면 여기부터 고친다.)

## 화면 방향

> **게이트: 화면을 그리는 첫 기능을 구현하기 전에 이 절이 채워져 있어야 한다.** 비어 있으면 그 자리에서
> 사용자에게 묻는다(CLAUDE.md '요구사항 정책').

1. **UI 형태**: Android 앱 + 웹(Flutter 한 벌)
2. **기준 기기·해상도**: 휴대폰 세로(폭 360~412dp)가 기준이다. 넓은 화면(폭 900px 이상 — 웹 데스크톱)에서는
   결과 카드를 **2열**로 놓는다(2026-09-11 사용자 결정).
3. **룩앤필의 기준**: **Material 3 + 아이콘 색 시드**(2026-09-11 사용자 결정). Flutter 기본 Material 3 위젯을 쓰고
   색은 아이콘의 파랑(#2E7FE0)을 시드로 Material 3가 자동 생성한다(남색 #0B1F4F는 심볼 안에서만 쓴다 — 시드는 하나뿐이라
   AI가 파랑을 골랐다). 커스텀 디자인은 없다. 사고대비물질 '우선 적용'은 강조색,
   삭제 항목은 흐리게. 2026-09-11 목업(검색 결과 카드, 구분별 수량 표)은 데이터 배치의 기준이다.
   - **앱 상단 헤더**(2026-09-11 사용자 요청): 왼쪽에 아이콘 심볼 + "FindChem"을 붙여 두고, 오른쪽에 '⋮'(더보기).
     누르면 메뉴가 열리고 일단 톱니바퀴 아이콘 + '설정' 항목 하나가 있다(설정 화면 자체는 F-002, Phase 005).
     2026-09-11 사용자 결정: 목업 확인 없이 이 설명대로 확정.
4. **다크모드 / 접근성 / 언어**: 시스템 설정을 따라 라이트/다크가 자동으로 바뀐다(Material 3 색 자동 생성).
   화면 언어는 한국어 하나. 시스템 글자 크기 확대에 레이아웃이 깨지지 않게 한다. 스크린리더 라벨 등 별도 접근성
   작업은 하지 않는다(2026-09-11 사용자 결정).
6. **검색 실행 시점**: 글자를 넣을 때마다 즉시 검색한다. 검색 버튼은 없다. 빈 입력이면 결과 영역이 비어 있다
   (2026-09-11 사용자 결정, F-001 수용 기준 테스트는 이 방식을 전제한다).
5. **앱 이름·아이콘**: 앱 이름은 **FindChem**이다. 아이콘은 **C 연결형**으로 확정했다(2026-09-11 사용자 결정).
   물음표 줄기가 삼각플라스크 입구로 이어지고, 물음표의 점이 목 안의 기포가 된다. 배경은 왼쪽 위 남색(#0B1F4F)에서
   오른쪽 아래 파랑(#2E7FE0)으로 가는 그라데이션이다. 확정본: [`docs/design/findchem_icon.svg`](design/findchem_icon.svg)

## 기능 요구사항

### F-001: 물질 검색
- **설명**: 검색창에 물질명(국문·영문)이나 CAS 번호를 넣으면 두 표에서 맞는 항목을 모두 보여준다.
  이름은 부분 일치로 찾고 **띄어쓰기는 무시한다**(2026-09-11 사용자 결정). 화면은 2026-09-11 목업대로 확정했다.
- **수용 기준** (테스트: `test/search/search_test.dart`·`test/ui/search_page_test.dart`, 실제 번들 데이터에 질의):
  - [x] '염화수소'(붙여 씀) → 원문이 '염화 수소'로 띄어 쓴 인체·생태 유해성 연번 306이 결과에 들어간다. 반대로 띄어 써서 넣어도 찾힌다
  - [x] 'GUAZATINE'과 'guazatine' → 둘 다 '구아자틴'과 같은 결과 2건(영문 대소문자 무시 — AI 기본값)
  - [x] '구아자틴' → 2건. 인체·생태 유해성 연번 4(구아자틴 염류)와 연번 5(구아자틴)
  - [x] '13516-27-3' → 1건. 인체·생태 유해성 연번 5. CAS가 여러 개인 항목의 두 번째 이하 CAS로도 찾힌다
  - [x] '50-00-0' → 2건. 사고대비물질 번호 1이 맨 위에 '사고대비물질 · 우선 적용'으로 나온다. 인체·생태 유해성
        연번 510은 그 아래에 나오고, "사고대비물질은 사고대비물질 규정수량을 적용합니다(별표2 일반기준 가)" 참고 문구가 붙는다
  - [x] 결과 머리에 전체 건수와 표별 건수가 나온다. 결과를 상한으로 자르는 경우에는 전체 건수와 '더 있음'을 함께 보여준다
  - [x] CAS 형식으로 입력해 0건이면 "염류·화합물 묶음 항목에 해당할 수 있으니 물질명으로도 검색해 보세요"라는
        안내가 나온다(2026-09-11 사용자 결정 (가))
  - [x] 항목 카드에는 다음이 모두 나온다: 국문명, 영문명, 표 이름과 연번, 고유번호(인체·생태 유해성만), CAS 전부,
        구분별 함량기준·최하위·하위·상위 규정수량(톤). 값은 원문 그대로(`0.2*`, `-`, `70% 초과`)
  - [x] CAS가 없는 항목(77건)에는 '묶음 항목 · CAS 없음' 표시가 붙는다
  - [x] `(삭제)` 항목(인체·생태 유해성 19건)은 결과 맨 아래에 흐리게 나오고 '삭제된 항목 · 규정수량 없음' 표시가
        붙는다(2026-09-11 사용자 결정). '톨루엔' → 사고대비물질 항목이 위에, 인체·생태 유해성 연번 439(삭제)가 맨 아래에 나온다.
        '123-33-1' → 연번 91(삭제) 1건이 나오고, 0건 안내는 뜨지 않는다
- **엣지케이스**: 빈 입력이면 검색하지 않는다(AI 기본값)
- **명세에 없어 AI 기본값으로 정한 것(2026-09-11, 구현 위치 `lib/search/search.dart`·`lib/ui/entry_card.dart`)** — 바꾸려면 여기부터 고친다:
  - 입력이 숫자·하이픈뿐이면 CAS **앞부분 일치**도 본다(입력 즉시 검색이라 타이핑 중에도 좁혀지게). 이름 검색은 항상 같이 한다.
    **하이픈은 무시한다 — '96297'로도 '96-29-7'(연번 1326)이 찾힌다**(2026-09-11 사용자 결정, 테스트 있음). 0건 안내는
    하이픈 뺀 숫자가 5~10자리일 때 띄운다('9999999'는 안내, '9999'는 이름 숫자일 수 있어 안내 없음)
  - 결과 상한은 **100건**. 넘으면 "앞 100건만 표시 · 더 있음"
  - 이름으로 넣어 0건이면 '결과 없음'만 표시(묶음 안내는 CAS 형식일 때만)
  - '우선 적용'·참고 문구는 같은 CAS가 **살아있는** 인체·생태 유해성 항목에도 있을 때만 붙는다. 예: 사고대비물질 톨루엔(108-88-3)의
    짝은 (삭제) 연번 439뿐이라 표시하지 않는다
  - 삭제 항목 카드에는 수량 표를 그리지 않는다(값이 전부 `-`). 표별 건수에는 삭제 항목도 센다
  - 2026-09-11 목업은 대화로만 합의했고 저장소에 파일이 없다 — 카드 배치의 정답은 위 수용 기준 문장이다
- **상태**: 완료(2026-09-11)

### F-003: 카드 공유
- **설명**: 결과 카드 오른쪽 위의 공유 아이콘을 누르면 그 카드 내용을 평문으로 공유한다(2026-09-11 사용자 결정, 형식은
  대화에서 예시 3건을 보고 확정). Android는 시스템 공유 창을 연다. 공유 창이 없는 브라우저(PC 웹 등)에서는 클립보드에 복사하고
  "복사했습니다" 알림을 띄운다. 메신저 글꼴은 고정폭이 아니라 표 대신 구분별 한 줄로 쓴다.
- **수용 기준** (테스트: `test/share/share_text_test.dart`·`test/ui/search_page_test.dart`, 실제 번들 데이터):
  - [x] 인체·생태 유해성 연번 510('50-00-0') → 아래 문자열과 한 글자도 다르지 않다. 참고 문구 줄은 참고 문구가 붙는 카드에만 들어간다
        ```
        [인체·생태 유해성] 포르말린; 포름알데히드
        Formalin; Formaldehyde
        연번 510 · 고유번호 97-1-345
        CAS 50-00-0

        규정수량(톤) 최하위 / 하위 / 상위
        · 급성, 함량기준 1%: 0.05 / 2 / 400
        · 만성, 함량기준 0.1%: 0.125 / 5 / 400

        ※ 사고대비물질은 사고대비물질 규정수량을 적용합니다(별표2 일반기준 가)

        FindChem · 「유해화학물질의 규정수량에 관한 규정」 (PDF 2026-07-20 기준)
        ```
  - [x] 사고대비물질 번호 42(염화수소) → 첫 줄이 `[사고대비물질 · 우선 적용] 염화수소`이고, 수량 줄은
        `· 함량기준 10%: 0.02 / 0.8 / 4`와 `· 염화수소 용액: 0.2* / 8* / 40*`이다(구분이 없으면 함량기준만, 값은 원문 그대로)
  - [x] 사고대비물질 번호 46(질산) → 함량기준에 이미 %가 있으면 그대로 둔다: `· 함량기준 70% 초과: 0.025 / 1 / 20`
  - [x] 삭제 항목(연번 91) → 수량 줄 대신 `삭제된 항목 · 규정수량 없음`. CAS 없는 항목(연번 4) → CAS 줄 대신 `묶음 항목 · CAS 없음`
  - [x] 마지막 줄의 날짜는 그 카드가 속한 표 PDF의 생성일이다. 생성일이 없으면 `(PDF … 기준)`을 빼고 고시명까지만 쓴다
  - [x] 검색 결과의 카드마다 공유 아이콘이 하나씩 있고, 누르면 그 카드의 공유 텍스트가 공유 창으로 넘어간다.
        공유 창을 열 수 없으면(예외) 같은 텍스트가 클립보드에 들어가고 "복사했습니다" 알림이 뜬다. 클립보드 쓰기까지
        거부되면 "공유하지 못했습니다" 알림이 뜬다(AI 기본값 2026-09-11 — 앱 내장 브라우저에서 둘 다 실패하는 것을 실측)
  - [x] (사용자 실테스트) Android 실기기에서 공유 아이콘 → 시스템 공유 창 → 카톡 등에 붙은 텍스트가 위 모양 그대로다
        — 2026-09-11 사용자 확인 통과
- **상태**: 완료(2026-09-11)

### F-002: 원천자료 update
- **설명**: 설정 메뉴의 '원천자료 update'에서 인체·생태 유해성 PDF와 사고대비물질 PDF를 올리면, 앱이 파싱해서
  검색에 쓰는 원천자료를 새것으로 바꾼다. 고시가 개정됐을 때 쓴다(2026-09-11 사용자 결정 — 종전의 "앱 재배포로
  갱신" 결정을 대체한다). **update는 기기마다 따로 한다**(2026-09-11 사용자 결정). 서버가 없으므로 한 기기에서
  올린 원천자료가 다른 기기나 웹에 전해지지 않는다.
- **수용 기준**:
  - [ ] 현재 `assets/`의 PDF 2개를 올리면 1,557건과 100건으로 파싱된다. 결과는 앱에 들어 있는 데이터와 같다
  - [ ] **두 PDF를 함께 올려야 한다**(2026-09-11 사용자 결정). 하나만 고르면 적용되지 않고, 무엇이 빠졌는지 알려 준다.
        두 파일을 서로 바꿔 고른 경우(인체·생태 유해성 자리에 사고대비물질 PDF)에도 적용되지 않는다
  - [ ] 파싱 검증(표 형식, 연번 연속)이 둘 중 하나라도 실패하면 기존 원천자료를 그대로 두고 실패 사유를 화면에 보여준다
  - [ ] 설정 화면에 현재 원천자료 정보가 나온다: 번들 / update 중 무엇인지, PDF 생성일, 표별 건수, 적용한 날짜
  - [ ] **'처음 데이터로 되돌리기'**(2026-09-11 사용자 결정)를 누르면 update한 원천자료를 지우고 앱에 들어 있던 데이터로
        돌아간다. 이후 검색 결과와 설정 화면의 원천자료 정보가 번들 기준으로 바뀐다
- **상태**: 미착수
