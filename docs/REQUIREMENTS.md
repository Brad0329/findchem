# FindChem 요구사항 (단일 원본)

> 기능 요구사항 + 수용 기준의 단일 원본. **요구사항이 바뀌면 대화로 합의만 하지 말고 이 파일을 즉시 갱신.**
> 완료 판정은 항상 이 문서를 기준으로 한다(에이전트를 쓰든 직접 대조하든).
> **새 F-번호는 CLAUDE.md의 '요구사항 ID 대장'에서 받아간다. 번호 재사용 금지.**

## 시스템 목표
- 물질명이나 CAS 번호를 넣으면 환경부 고시 「유해화학물질의 규정수량에 관한 규정」에서 그 물질의 규정수량을
  바로 찾아 준다. 대상은 두 표다.
  - [별표 2] 인체급성·인체만성·생태유해성 물질별 규정수량
  - [별표 3] 사고대비물질별 규정수량
- 사용자는 본인과 사내 소수다. Android 앱과 웹으로 제공하며, 둘 다 Flutter 한 벌로 만든다. 서버는 없다.

## 용어 (화면 표시) — 2026-09-11 사용자 결정
- [별표 2] → **"인체·생태 유해성"**, [별표 3] → **"사고대비물질"**.
- 화면에는 이 두 이름을 쓰고 "별표2", "별표3"은 쓰지 않는다. 데이터 내부 식별자는 SCHEMA.md를 따른다.

## 사용자/권한
- 역할을 구분하지 않는다. 앱을 가진 사람은 누구나 조회할 수 있고 원천자료 update(F-002)도 할 수 있다.
  (AI가 채운 기본값이다. 달라지면 여기부터 고친다.)

## 기능 요구사항

### F-001: 물질 검색
- **설명**: 검색창에 물질명(국문·영문)이나 CAS 번호를 넣으면 두 표에서 맞는 항목을 모두 보여준다.
  이름은 부분 일치로 찾고 **띄어쓰기는 무시한다**(2026-09-11 사용자 결정). 화면은 2026-09-11 목업대로 확정했다.
- **수용 기준**:
  - [ ] '염화수소'(붙여 씀) → 원문이 '염화 수소'로 띄어 쓴 인체·생태 유해성 연번 306이 결과에 들어간다. 반대로 띄어 써서 넣어도 찾힌다
  - [ ] 'GUAZATINE'과 'guazatine' → 둘 다 '구아자틴'과 같은 결과 2건(영문 대소문자 무시 — AI 기본값)
  - [ ] '구아자틴' → 2건. 인체·생태 유해성 연번 4(구아자틴 염류)와 연번 5(구아자틴)
  - [ ] '13516-27-3' → 1건. 인체·생태 유해성 연번 5. CAS가 여러 개인 항목의 두 번째 이하 CAS로도 찾힌다
  - [ ] '50-00-0' → 2건. 사고대비물질 번호 1이 맨 위에 '사고대비물질 · 우선 적용'으로 나온다. 인체·생태 유해성
        연번 510은 그 아래에 나오고, "사고대비물질은 사고대비물질 규정수량을 적용합니다(별표2 일반기준 가)" 참고 문구가 붙는다
  - [ ] 결과 머리에 전체 건수와 표별 건수가 나온다. 결과를 상한으로 자르는 경우에는 전체 건수와 '더 있음'을 함께 보여준다
  - [ ] CAS 형식으로 입력해 0건이면 "염류·화합물 묶음 항목에 해당할 수 있으니 물질명으로도 검색해 보세요"라는
        안내가 나온다(2026-09-11 사용자 결정 (가))
  - [ ] 항목 카드에는 다음이 모두 나온다: 국문명, 영문명, 표 이름과 연번, 고유번호(인체·생태 유해성만), CAS 전부,
        구분별 함량기준·최하위·하위·상위 규정수량(톤). 값은 원문 그대로(`0.2*`, `-`, `70% 초과`)
  - [ ] CAS가 없는 항목(77건)에는 '묶음 항목 · CAS 없음' 표시가 붙는다
- **엣지케이스**: 빈 입력 / 공백·대소문자 차이 / 삭제 항목 → '미결 질문' 참조
- **상태**: 미착수

### F-002: 원천자료 update
- **설명**: 설정 메뉴의 '원천자료 update'에서 인체·생태 유해성 PDF와 사고대비물질 PDF를 올리면, 앱이 파싱해서
  검색에 쓰는 원천자료를 새것으로 바꾼다. 고시가 개정됐을 때 쓴다(2026-09-11 사용자 결정 — 종전의 "앱 재배포로
  갱신" 결정을 대체한다). **update는 기기마다 따로 한다**(2026-09-11 사용자 결정). 서버가 없으므로 한 기기에서
  올린 원천자료가 다른 기기나 웹에 전해지지 않는다.
- **수용 기준** (초안 — 미결 질문에 답을 받은 뒤 확정):
  - [ ] 현재 `assets/`의 PDF 2개를 올리면 1,557건과 100건으로 파싱된다. 결과는 앱에 들어 있는 데이터와 같다
  - [ ] 파싱 검증(표 형식, 연번 연속)에 실패하면 기존 원천자료를 그대로 두고 실패 사유를 화면에 보여준다
  - [ ] 설정 화면에 현재 원천자료 정보가 나온다: PDF 생성일, 표별 건수, 적용한 날짜
- **상태**: 미착수

## 미결 질문
- F-001: 인체·생태 유해성의 `(삭제)` 항목 19건을 결과에 보여줄까, 뺄까? 이 항목들은 **현재 PDF에 들어 있다**.
  구분이 `(삭제)`이고 값은 전부 `-`다(예: 108 메틸 에틸 케톤, 414 자일렌, 439 톨루엔). 그중 5건은 사고대비물질에
  들어 있다. 빼면 해당 CAS로 검색했을 때 0건과 '묶음 항목' 안내가 나와 오해를 줄 수 있다
- F-002: 두 PDF를 반드시 함께 올려야 할까, 하나만 바꾸는 것도 허용할까?
- F-002: 앱에 처음 들어 있던 데이터로 되돌리는 기능이 필요할까?
